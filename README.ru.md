# CyberNavigator (КиберНавигатор)
[English](README.md) | **Русский**

CyberNavigator (КиберНавигатор) — онлайн-платформа со статьями о цифровой гигиене и симулятором мошеннических схем.
Симулятор мошеннических схем — онлайн-игра, в которой игрок становится целью мошенника в мессенджере. Игроки должны распознать характерные признаки обмана и не попасться на уловку.

### Стек технологий
- [Docker Swarm](https://docs.docker.com/engine/swarm/) — оркестрация контейнеров
- [NuShell](https://www.nushell.sh/) — структурированная терминальная оболочка
- Golang — весь бэкенд
- NextJS + TypeScript — весь фронтенд
- Postgres — метаданные сервисов
- Mongo — тексты статей
- Nginx — обратный прокси + SSL-сертификаты + маршрутизация трафика
- Docker — очистка мёртвых контейнеров

### Подготовка
1. Отредактируйте /nginx/conf и /nginx/scripts. **Измените домен**
2. Войдите в nushell командой `nu`
3. Активируйте модуль manage.nu командой `use manage.nu *`
4. Инициализируйте секретные данные командой `init`
5. Отредактируйте секретные данные, расположенные по пути /secrets/env/*
6. Вернитесь в корень проекта
7. Создайте секреты командой `secrets-create`

### Управление проектом
Используйте модуль manage.nu в nushell командой `use manage.nu *`
- deploy env — развёртывание проекта
- down — удалить стек
- update serviceName — обновить сервис и версию его образа
- secrets-update — использовать после изменения файлов /secrets/env/*.secret.env
- start serviceName — установить 1 реплику для сервиса serviceName
- stop serviceName — установить 0 реплик для сервиса serviceName

### Разработка
> Измените владельца образов «neknarej» на своего в файлах: compose.*.yaml и manage.nu. Затем перезагрузите модуль manage.nu командой `use manage.nu *`
- send — отправить все образы в Docker Hub. `send serviceName` — отправить только serviceName
- tag — привязать локальный образ к онлайн-репозиторию
- push — отправить локальный образ в онлайн-репозиторий
- build — собрать образ

### О коде проекта
Проект поддерживает 3 окружения:
- local — используется на хосте
- dev — используется внутри Docker для локальной разработки (переключает проект на работу в локальной сети)
- prod — используется внутри Docker в продакшене (переключает проект на работу во внешней сети)

> gateway-server и сервисы используют соединение, защищённое через mTLS
>
> Каждый сервис имеет Swagger UI по адресу `service_url/swagger`
>
> Все страницы Swagger UI сервисов доступны по адресу `gateway-server_url/swagger`
>
> Чтобы отредактировать спецификацию OpenAPI, отредактируйте файлы в /swagger/docs/*. Затем запустите nu-скрипт `nu /nu/swagger-gen.nu FileName`. **Важно!!!** Указывайте только имя файла *.swagger.yaml. Если вы создаёте новый файл, отредактируйте nu-скрипт. Затем закоммитьте изменения и обновите сервис командой `go get your-repo/swagger@commit-hash`
